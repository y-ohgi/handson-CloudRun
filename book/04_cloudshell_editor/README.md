# 4. Cloud Shellとエディタの使い方

2章ですでにCloud Shellエディタでファイルを作り、ターミナルで `docker build` を実行しました。  
5章以降はコマンドの数も増えるので、ここで一度、エディタとターミナルの操作を整理しておきます。

## 1. 画面構成

Cloud Shell エディタを開くと、3つの領域に分かれています。

- **左側: ファイルツリー** — `$HOME`(`~/cloudrun-handson/` など)配下のファイル・フォルダ一覧
- **中央: エディタ** — VS Code ベースで、拡張機能・シンタックスハイライトなど一通り揃っています
- **下部: ターミナル** — コマンドを実行する画面。タブで複数開けます

右上の[ウェブでプレビュー]ボタン(2章で使った、ウィンドウに目が描かれたアイコン)は、ターミナルで起動したプロセスをブラウザで開くためのものです。

## 2. ファイル・フォルダを操作する

ファイルツリーを右クリックすると、新規ファイル・新規フォルダ・リネーム・削除ができます。  
ファイルの保存は**自動ではありません**。編集後は `Cmd+S`(macOS)/ `Ctrl+S`(Windows/Linux)で保存してください。

> **詰まったら:** 5章以降で「ファイルを書き換えたのにコマンドの結果が変わらない」と感じたら、エディタのタブ名の横に丸印(●)が出ていないか確認してください。丸印は未保存の印で、保存すればファイル名だけの表示に変わります。

## 3. ターミナルを使う

下部パネルの `+` ボタンで、新しいターミナルタブを追加できます。  
複数のターミナルは同じ Cloud Shell 環境(同じ `$HOME`)を共有するので、たとえば片方でログを流しっぱなしにしながら、もう片方でコマンドを打つ、という使い方ができます。

ターミナルとエディタは同じファイルシステムを見ているため、エディタで保存した変更は即座にターミナルから見えます。  
一方で、Cloud Shell が切断されると新しいターミナルセッションになり、`export` した環境変数はすべて消えます(ファイルは `$HOME` に残るため消えません)。環境変数が消えたときの復旧手順は[0章の復旧ブロック](../00_preparation/README.md#復旧ブロック困ったらここ)にまとめてあります。

## 4. エディタとターミナルを往復する

このハンズオンの基本サイクルは、2章で体験した以下の繰り返しです。

1. エディタでファイルを編集する
2. 保存する(`Cmd+S` / `Ctrl+S`)
3. ターミナルでコマンドを実行する(`docker build`、`gcloud run deploy` など)
4. 結果をブラウザやターミナルの出力で確認する

5章以降もこのサイクルは変わりません。手が止まったら、まず「保存し忘れていないか」を疑ってください。

## 5. 覚えておくと速いショートカット

必須ではありませんが、知っておくと操作が速くなります。

| 操作 | ショートカット |
|---|---|
| コマンドパレットを開く | `Cmd+Shift+P` / `Ctrl+Shift+P` |
| ファイルを名前で開く | `Cmd+P` / `Ctrl+P` |
| ファイル内を検索 | `Cmd+F` / `Ctrl+F` |
| プロジェクト全体を検索 | `Cmd+Shift+F` / `Ctrl+Shift+F` |

## まとめ

- 操作は「エディタで編集 → 保存 → ターミナルで実行 → ブラウザで確認」の往復が基本
- 保存を忘れると変更が反映されない。タブの丸印(●)で未保存を見分けられる
- Cloud Shell の再接続でファイルは消えないが、環境変数は消える

次の5章から、実際に Cloud Run へのデプロイを進めていきます。
